# Блокнотик: публичный сайт

- Этот репозиторий содержит только публичный сайт `sng216-web/bloknotik-recipes`. Внутренняя AI-редакция находится в отдельном репозитории; не изменять его в рамках задач сайта.
- Стек: Astro, статическая генерация, TypeScript strict, Zod. Не добавлять серверные endpoint, которые не работают на GitHub Pages.
- Источник схемы Recipe — `src/lib/recipe-schema.ts`. Все данные проходят runtime-валидацию. Типы выводить из Zod; не дублировать контракты вручную.
- Реальный контент — `src/content/recipes/`. Демо — только `fixtures/recipes/`, с `demo: true`, `status: draft`. Демонстрации не являются рецептами для приготовления.
- В страницы публикаций, поиск, RSS, sitemap и Recipe JSON-LD включать только `isPublished`-материалы: не демо, положительный QA текущей revision, подтверждённая дата не из будущего.
- Не создавать фиктивные опубликованные статьи, рейтинги, отзывы, авторов, время и калорийность. Необязательные факты выводить только из полей с `confirmed: true`.
- Все изображения широкоформатные, с alt и сведениями о правах. Перед импортом проверять реальный локальный файл, размеры, границы пути. Не скачивать произвольные URL из import payload.
- Публичные постоянные URL строить через `pathFor` / `absoluteUrl`, учитывая SITE_URL и подкаталог GitHub Pages. Сохранять slug при обновлении.
- Весь внешний текст экранировать. JSON-LD сериализовать через `safeJson`, XML через `xml`, клиентский поиск через textContent, не innerHTML.
- Импорт утверждённого материала пишет только staging и создаёт PR. Не публиковать автоматически. `content:publish` — отдельный редакционный шаг с подтверждённой датой и проверкой revision.
- Положительный QA привязан к SHA-256 редакционного содержимого через approval.contentDigest. Не пересчитывать его автоматически при импорте или выпуске для обхода нового review. Известные demo ID, slug и тестовые инструкции не выпускать даже после изменения флага demo.
- Существующие n8n workflows неприкосновенны. Репозиторий не создаёт и не изменяет workflows n8n; он предоставляет собственный GitHub Actions importer для будущего процесса.
- Секреты не хранить в репозитории, frontend и примерах. GitHub credential будущего n8n хранится в его credential store; GitHub Actions использует краткоживущий GITHUB_TOKEN.
- Тестовые утверждённые записи создавать только в памяти или временных каталогах. Никогда не добавлять их в настоящий каталог публикаций ради теста.
- Перед PR: `npm ci --ignore-scripts`, `npm run check`, `npm run test:browser`, `git diff --check`. Chromium для browser-тестов: `npx playwright install --with-deps chromium`.
- Проверять main и резервную ветку перед миграциями. Работать через PR, не делать merge и не заявлять о работающем хостинге без фактического подтверждения.
