## Граница автоматических гарантий

Импортёр принимает только approved non-demo Recipe и записывает **только staging**. Workflow импорта не вызывает content:publish, не меняет каталог публикаций, не делает auto-merge и не выдаёт receipt успешного deployment. Эти ограничения и невозможность выпуска известных fixture/неутверждённых данных покрыты тестами. Реальный каталог при аудите оставался пустым.

Hash доказывает неизменность относительно предоставленного QA, **не достоверность рецепта и не личность проверяющего**. Доверенный обладатель write-доступа может сформировать другой JSON, новый hash или изменить сам код. Универсально распознать вымышленный рецепт по структуре невозможно; такого обещания система не даёт. Поэтому перед реальной автоматизацией нужны доверенное содержательное review и защита основной ветки. Нельзя использовать helper reseal из tests для утверждения реальных материалов.

## Остающиеся проблемы до публичного запуска

1. **Хостинг не включён, публичные URL — 404.** Владелец должен включить Pages и получить успешный deployment.
2. **Код ещё в открытом PR, основная ветка проекта настроена неверно.** Требуются review/merge и default branch main; иначе repository_dispatch не найдёт workflow.
3. **main не защищена.** Branch API сообщает protected=false, rulesets пусты. Перед подключением автоматических источников включить PR/review и обязательный Site checks, запретить force/delete и не давать импортёру bypass. Эти административные настройки аудит не менял.
4. **Нет реальных проверенных статей.** Нельзя считать демо стартовым пакетом или основанием для подключения Дзена. Контент требует отдельной подготовки и QA.
5. **Внешние процессы ещё не проверены end-to-end.** Нет проверенного dispatch из n8n, публичного release receipt и синхронизации Notion; нынешние тесты используют временные файлы/fake-адаптеры.
6. **Нет внешнего мониторинга.** После запуска нужно проверить реальные HTTP, canonical, 404, feed и отсутствие URL демо с фактического домена; затем выбрать мониторинг и контроль ошибок.

Чтение части административных настроек Actions текущей интеграцией ограничено HTTP 403 Resource not accessible by integration. Это не отказ Git push; окончательную политику Pages/Actions владелец должен проверить в Settings. Автоматическое расписание выпуска не реализовано: будущая дата сама не запускает static rebuild.

## Развёртывание

1. Проверить текущий PR #1 и зелёный Site checks. Локально: `npm ci --ignore-scripts`, `npm run check`, `npx playwright install --with-deps chromium`, `CI=true npm run test:browser`.
2. В Settings назначить main основной, включить защиту PR/review/CI и проверить права Actions. Для будущего staging-импорта отдельно разрешить Actions создавать PR, если политика запрещает это по умолчанию.
3. Settings → Pages → Build and deployment → Source: **GitHub Actions**. Для другого домена задать публичную repository variable SITE_URL с HTTPS и завершающим `/`, настроить домен/DNS отдельно. По умолчанию используется `https://sng216-web.github.io/bloknotik-recipes/`.
4. Слить PR после review. Pages workflow выполняется только из main. Если merge произошёл до включения Pages, запустить `Deploy static site to Pages` вручную на main после настройки.
5. Дождаться успешного deployment и использовать URL, возвращённый GitHub. Не считать зелёный build или запись source доказательством публикации.
6. Проверить GET главной, categories, about, search, rss.xml, sitemap.xml и robots.txt: 200, корректные Content-Type и тела. Неизвестный рецепт должен возвращать настоящий 404. Проверить HTTPS, домен/base path, canonical, OG, мобильный экран и изображения.
7. При пустом реальном каталоге RSS и search-index должны оставаться пустыми. Demo не должно быть в sitemap/RSS/Recipe JSON-LD; noindex на demo должен сохраняться. Ничего тестового не выпускать ради наполнения.
8. Только после подготовки настоящего материала: доверенный QA с contentDigest → staging import/PR → отдельный редакционный content:publish с подтверждённой датой → review/merge → deployment → проверка фактического permanent URL. Только после этого внешняя редакция может отметить материал опубликованным.

Подключение Дзена и публикация тестовых материалов в эту инструкцию запуска не входят.
