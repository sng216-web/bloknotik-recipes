# Единая схема Recipe

`src/lib/recipe-schema.ts` — источник runtime-валидации и TypeScript-типа `Recipe`. `.strictObject` отклоняет неизвестные поля. Используется при чтении каталога, импорте, генерации страниц, RSS, sitemap и поискового индекса.

| Поле | Контракт |
| --- | --- |
| schemaVersion | Строка `1`; неизвестная версия отклоняется |
| id, revision | Постоянный ID и положительная целая revision |
| slug | Уникальный, неизменяемый URL slug: латиница в нижнем регистре, цифры и разделяющие дефисы |
| title, description, introduction | Непустой текст; ограничения длины заголовка и описания |
| ingredients | Непустой список `{ name, quantity }`; количество с единицей — явная строка |
| steps | Непустой список `{ text, tip? }`; входной HTML не исполняется |
| images | Локальные `/images/name.webp` (также jpg/jpeg/png/avif), alt, размеры, kind cover/step, credit, rights и необязательный sourceUrl |
| dates | created, updated, published; ISO 8601 с часовым поясом, published null до выпуска |
| category | breakfast, soups, mains, salads, baking, desserts |
| status | draft, approved, published, archived |
| demo | Обязательный boolean; true разрешён только для draft |
| tags, sources | Теги и реальные HTTPS-источники; для approved/published источники обязательны |
| approval | null для черновика или reviewId, reviewer, revision, approvedAt, contentDigest и шесть положительных проверок |
| details | Необязательные servings, prepMinutes, cookMinutes, caloriesKcal, каждое `{ value, confirmed: true }` |

Нужен ровно один cover, все изображения landscape. Файлы помещаются в public/images отдельным review; импорт не скачивает произвольные URL. Их реальные размеры и границы файловой системы проверяются через sharp. `rights` — декларация редактора, а не автоматическое доказательство лицензии.

Approval относится к текущей revision и включает completeness, cookingLogic, foodSafety, originality, facts и mediaRights. Редактор отвечает за действительное прохождение проверок: схема проверяет форму и соответствие версии, но не умеет удостоверять вкус блюда или безопасность пищи.

`contentDigest` — SHA-256 канонически сериализованных полей Recipe без approval, status и служебных dates.updated/dates.published. Поле dates.created входит в hash. Порядок ключей объектов не влияет на hash; порядок ингредиентов/шагов влияет. Функция `contentDigest` экспортируется из src/lib/content-digest.ts для доверенного редакционного инструмента. Digest должен быть зафиксирован после содержательного review; importer и release не подписывают и не утверждают материал сами. Это проверка неизменности, а не цифровая подпись или доказательство достоверности.

Изменение содержимого без нового review вызывает ошибку. Demo ID, demo-теги и известные fixture slug/инструкции дополнительно зарезервированы: одного изменения demo на false недостаточно для выпуска. Это защита от известных тестовых материалов, а не универсальный распознаватель вымышленных рецептов.

Временные данные: created ≤ approvedAt ≤ updated. Для published нужна дата публикации между created и updated, не из будущего для допуска в сайт. При обновлении реальной статьи сохраните первоначальную дату публикации и slug, увеличьте revision, обновите QA и updated.

Порции и время заполняются только при проверке. caloriesKcal означает подтверждённую калорийность одной порции; если она неизвестна, поля не должно быть. Рейтинги, отзывы и вымышленные персональные авторы отсутствуют. Публичным автором разметки является организация Блокнотик.

## Каталоги и доступ

- `src/content/recipes/<slug>.json`: настоящий контент. Прочитывается сборкой; draft/approved/archived и будущие публикации не получают страницы `/recipes/`.
- `content/incoming/<slug>.json`: staging после импорта; сайт его не читает.
- `fixtures/recipes/<slug>.json`: явные demo drafts. Используются только `/demo/<slug>/`, имеют предупреждение и noindex.

Один и тот же `isPublished` фильтрует страницы, RSS, sitemap, JSON-LD и индекс поиска. Список опубликованных записей сейчас пуст. RSS валиден без items. Sitemap включает настоящие навигационные страницы, а не выдуманные публикации.

## Первая реальная статья

1. Приготовить и проверить рецепт, источники, изображения и необязательные факты.
2. Создать утверждённый Recipe (demo false, status approved, dates.published null) с действительным QA.
3. Импортировать в staging и проверить PR. Не подменять демо-файл флагом demo false.
4. Отдельным редакционным шагом подготовить выпуск через content:publish с подтверждённой датой.
5. Выполнить проверки, review, merge и Pages deployment.
6. Проверить публичную страницу и feed. Только после этого обновить внешний редакционный статус на опубликовано.

Файл в source со статусом published означает разрешённое содержание production-сборки; сам по себе он не доказывает, что Pages уже выполнил deployment. До подтверждения фактического URL нельзя сообщать n8n/Notion об успешной публикации.

Подготовка того же выпуска с той же датой (включая эквивалентный timezone) возвращает unchanged, не перезаписывая файл. Новая утверждённая revision должна сохранять исходный slug/дату публикации и увеличивать updated. Файлы пишутся атомарно, symlinks отклоняются; параллельные CLI-процессы защищены lock-файлом .content-publication.lock. После аварийного завершения stale lock можно удалить вручную только после проверки отсутствия другого release-процесса.
