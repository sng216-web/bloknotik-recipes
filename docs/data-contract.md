# Входящий контракт редакции 2.0.0

Сайт принимает SiteHandoff из `contracts/v2/handoff.ts`, нормализует его в существующий ImportEnvelope и пишет только staging.
`src/lib/editorial-contract.ts` экспортирует runtime-схему, преобразование и stageEditorialHandoff.
Обе CLI-точки импортирования применяют один normalizer; GitHub Actions workflows не изменены.

Единый редактируемый источник — безопасная часть контрактов редакции; в этом репозитории хранится автономный артефакт с SHA-256 manifest.
`npm run contracts:check` выявляет изменение файлов без синхронизации. Общий suite и общая синтетическая фабрика запускаются в CI обоих repo.
Публичная сборка никогда не обращается к приватному GitHub. Артефакт не содержит карточек Notion, prompts, credentials, исследовательских заметок или реальных статей.

| Слой | Каталог/контракт | Публичное включение |
| --- | --- | --- |
| Выпущенные исходники | src/content/recipes/*.json | Только isPublished: non-demo, текущий digest/QA, подтверждённая дата не из будущего |
| Staging | content/incoming/*.json | Никогда не читается каталогом страниц/RSS/sitemap/поиска |
| Ledger импорта | content/imports/*.json | Операционные ID/hash; не страницы |
| Demo | fixtures/recipes/*.json | Только существующие /demo/, draft/noindex, без Recipe JSON-LD и RSS/sitemap |
| Общая тестовая фабрика | contracts/test-support/ | Только тесты в памяти/временных каталогах; не loader контента |
| Медиа | public/images/ | Проверяются реальный файл, путь, сигнатура/MIME, размеры, EXIF, alt, права и source |
| Полный безопасный исходный payload | recipe.editorial | Сохраняет facts/content/media без потери; технические поля не отображаются как текст страницы |

Astro Content Collections не использовались в исходном сайте: существующий строгий catalog loader сохранён.
RecipeSchema v1 остаётся форматом хранения, editorial.schemaVersion = 2.0.0 обозначает исходный контракт.
Входной source contentDigest = SHA-256 канонического payload v2; approval.contentDigest сайта = прежний hash проекции Recipe v1.
Второй hash вычисляется после проверки исходного QA, а не для переодобрения изменённого содержания.
Ингредиенты и технология выводятся исключительно из facts. Схема блокирует расхождение проекции и исходного payload.
Неподтверждённые порции/время не подставляются; рейтинги/калорийность/отзывы не создаются.
SEO title используется отдельно от H1; повествование, советы, финал и чистое изображение выводятся существующими компонентами и стилями.

Новые обложки строго 16:9; clean — отдельный файл без наложений, именно его URL попадает в Recipe JSON-LD.
Исторические demo-иллюстрации 1600×1000 оставлены в draft без изменений файлов и дизайна. Выпустить их нельзя.

Импорт не публикует и не меняет live каталог. importId детерминирован из stage idempotencyKey;
повтор с другим payload блокируется, постоянные id/slug и revision защищены существующим ledger.
Файловый lock защищает одновременные локальные импорты; оставшийся после аварии lock требует сверки.
prepareRelease остаётся отдельной редакционной операцией. site status=published означает допуск исходника в статическую сборку,
а не доказательство deployment/public_verified. Доказательства этих стадий ведутся редакцией отдельно.
Проверка public page, транспорт n8n и полноценный механизм выпуска не реализуются этим PR.

При обновлении нужна новая версия безопасного артефакта и парные PR. После экспорта из источника:

```bash
npm ci --ignore-scripts
npm run check
npm run test:browser
```

Не изменяйте schemas/fixtures внутри contracts вручную. Сверка двух checkout производится exporter с `--target <site-root> --check` из редакции.
Локальный manifest — проверка целостности, не замена авторизации review.
